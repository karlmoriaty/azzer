## 1. 产品定义

### 1.1 三条入口

| 入口 | 触发条件 | 处理路径 | 人声拟真上限 | 整首成品感 |
|---|---|---|---|---|
| **A 直通** | 源音色 ≈ 目标音色（用户唱自己的歌） | 跳过 RVC，只做修复 + 拟真化 + 母带 | **最高** | 取决于伴奏 |
| **B 换音色** | 源 ≠ 目标，源是干声或清唱 | 分离 → 修复 → RVC → 拟真化 | 高 | 取决于伴奏 |
| **C 成品翻唱** | 源是发行成品（含伴奏） | 集成分离 → 修复 → RVC → 拟真化 | 中（分离损失不可逆） | **高**（继承原编曲） |

**注意 A 与 C 的反向关系**：C 的人声拟真上限最低，但整首成品感可能最高——因为伴奏是原版商业编曲。这两个是独立评分维度，不能合成一个"好不好"。

### 1.2 三档预设（三角权衡只能取二）

```
        拟真（像真人）
           /\
          /  \
         /    \
   好听 ─────── 保真（保留原唱这一版）
```

| 预设 | 拟真 | 好听 | 保真 | 关键参数 |
|---|---|---|---|---|
| **原件修复**（默认） | ★★★ | ★★ | ★★★ | 不过 RVC、不修音高、不注入，只做修复 + 混音 + 母带 |
| **精修翻唱** | ★★★ | ★★★ | ★★ | RVC + 音高修正（`preserve_ratio` 0.85）+ 拟真化 + 叠层 |
| **重制演绎** | ★★ | ★★★ | ★ | 走符号层重渲染（YuE2 按谱重唱），全部重新生成 + 拟真化 |

界面用用户的话表达，不用抽象词：

| 用户会说 | 对应 |
|---|---|
| "把我唱的修干净点，别改我的唱法" | 原件修复 |
| "用我的声音唱这首歌，但唱得比我好" | 精修翻唱 |
| "要一个全新版本，只要是我的音色" | 重制演绎 |

### 1.3 不做清单

| 不做 | 原因 |
|---|---|
| 一句话生成爆款 | 不与 Suno 打正面战场，音质不是可竞争维度（§2.2 W4） |
| 实时演唱 | 延迟目标 8–20 分钟，不是 200ms |
| 通用 DAW | 编辑收敛到旋律/和弦/结构/段落，不做波形自由剪辑 |
| 任意人声克隆 | 只做已授权音色库 |
| 从零写歌 | v3 不覆盖；保留接口给 v1.1 的生成侧 |

### 1.4 与商业产品的真实差距

| 维度 | Suno v5.5（2026-11 核对） | Azzer | 判定 |
|---|---|---|---|
| 音色克隆 | Voices：录音 + 验证，仅本人、18+、部分地区不可用 | RVC 本地，模型归用户、可迁移、无地域限制 | **胜**（胜在归属） |
| 保留原演绎 | Cover 是重新演绎，phrasing 会变 | replace 保留源全部 F0/timing/气口 | **胜**（结构性） |
| 局部编辑 | Studio 段落级重生成 | 音符级 patch（重制档） | **胜** |
| 离线 / 数据归属 | 云端 | 全本地 | **胜** |
| 分轨 | 12 轨，用模型内部多轨表示 | 信号级分离 | **负** |
| 整体音质 / 母带 | 整轨生成 + 内置母带 | 分离干声重建 + 自建母带链 | **负** |
| 中文咬字 | v5 主流语种强 | 依赖源 + RVC，待实测 | **负（待测）** |
| 出歌速度 | <1 分钟 2 首 | 11–20 分钟 | **负（数量级）** |

**禁止表述**：不得说"效果超越 Suno"、"达到商业发行水准"。依据见 §2.2 W4 与 §2.3。

## 2. 技术判断

### 2.1 核心命题

> **真人演唱的信息本来就在源里。所有模型的作用是别把它做坏，而不是把它做得更好。**

真人的气口、呼吸、口腔声、音准的微小偏差、时值的弹性——这些不需要生成。而链路每一步都在**删掉**它们：去混响删空间、降噪删底噪、修音删活人味、压缩删动态、单轨删厚度。

所以工程重心是**减损失**，可量化、可验收。

### 2.2 四处承重墙

| # | 承重墙 | 事实 | 架构后果 |
|---|---|---|---|
| **W1** | YuE2 权重 CC BY-NC 4.0，非商业 | 代码 Apache-2.0，权重非商业；商用需授权 | 引擎可替换；发行版不捆绑权重；调度器按 `commercial` 标志拦截。仅"重制演绎"档使用 |
| **W2** | 本机 8GB 跑不动 YuE2 官方配置 | 官方要 24GB；Q8_0 约 4.8GB 属非官方支持 | **主链路不依赖 YuE2**，因此 8GB 可行；重制档走 T1/T2 |
| **W3** | 符号层局部修改 ≠ 声学层局部重渲染 | 全曲一次性渲染，改一个音符要重跑整曲 | Graft（嫁接）+ Seam QA + 自动降级；仅在重制档启用 |
| **W4** | 整体音质打不过 Suno，是架构决定的 | Suno 从零生成整轨 + 内部 12 轨 + 内置母带；我们多一道不可逆分离损失 | 目标不定在"音质超越"；靠母带链、人声叠层、分离升级缩小差距 |

### 2.3 成功概率（工程估算，待实测替换）

先说方法：把链路拆成独立环节、按失败概率连乘，再用 best-of-N 做相关性修正。数字会随实测调整，排序与量级可靠。

| 定义 | 判断标准 | 概率 |
|---|---|---|
| **D1 人声听不出是 AI** | 30 人盲测识破率 ≤40% | **50–70%** |
| **D2 整首像商业 Demo** | 编曲、混音、母带、人声整体达标 | **30–70%** |
| **D3 与 Suno 盲测打平** | 整体偏好胜率 ≥45% | **15–55%** |

**区间跨度来自一个变量：伴奏是原版还是重新生成。**

| 源 | 伴奏 | 整首成品感 | 与 Suno 打平 |
|---|---|---|---|
| 带伴奏成品 | 保留原伴奏 | **60–70%** | 45–55% |
| 清唱 | ACE-Step 生成 | **25–35%** | 15–25% |

环节分解（A 级源 / 8GB）：

| 环节 | 成功率 | 是否可被 best-of-N 挽救 |
|---|---|---|
| 分离保住人声 | 0.95（干声）/ 0.85（成品） | 否（8 个 take 共享同一次分离） |
| RVC 转换无致命退化 | 0.80 | 是 |
| 高频重建不引入假谐波 | 0.75 | 部分 |
| 拟真化不过头 | 0.92 | 是 |
| **单 take** | **0.52** | — |
| **best-of-8**（筛选噪声折扣 0.7） | **0.72** | — |

`D2 ≈ D1 × 伴奏 × 混音`：原伴奏 0.72×0.95×0.90 ≈ 0.62；生成伴奏 0.72×0.40×0.90 ≈ 0.26。

**变量影响量级**：源质量 ±25 个百分点（最大杠杆）＞ 是否保留原伴奏 ±20 ＞ 训练数据 ±15 ＞ 硬件 8→24GB +8~12 ＞ 调参 ±5（最不划算）。

**基本不可能（<10%）**：C 级源、音域超限不移调、训练数据 <10 分钟或带伴奏训、跨性别移调不做 formant、期待唱功提升。

### 2.4 硬件阶梯

| 档位 | 硬件 | 能跑 | 用途 |
|---|---|---|---|
| **T0** | RTX 4060 Laptop 8GB / 16GB RAM | 分离、RVC、修复（分块）、ACE-Step 和声、母带 DSP | **主链路全通**（A/B/C 入口） |
| **T1** | 24GB 单卡 | 上述 + YuE2（量化/BF16）+ 不分块修复 + best-of-16 | 重制档、质量优先 |
| **T2** | 24–80GB / 多卡 | 全部 + LoRA 训练 | 训练与高峰 |

**T0 的边界**：YuE2 不可用（官方 24GB）；ACE-Step LoRA 大概率 OOM。所以"重制演绎"档在 T0 不承诺。

## 3. 系统架构

### 3.1 六层

```
┌──────────────────────────────────────────────────────────────┐
│ L5 体验    React + TS：上传 / 预设选择 / A-B 对比 / 差异高亮    │
├──────────────────────────────────────────────────────────────┤
│ L4 编排    FastAPI：任务编排、门禁判定、SSE 推送、报告          │
├──────────────────────────────────────────────────────────────┤
│ L3 计划    Song IR（谱面 / 表现层 / 渲染计划）+ LLM Planner     │
├──────────────────────────────────────────────────────────────┤
│ L2 调度    队列 / 显存仲裁 / 三级缓存 / 路由 / Graft / Seam QA  │
├──────────────────────────────────────────────────────────────┤
│ L1 引擎    [Demucs][MDX23C][UVR][RVC][ACE-Step][YuE2][DSP]     │
│            每个 = 独立 venv 的 sidecar + Capability Manifest    │
├──────────────────────────────────────────────────────────────┤
│ L0 资产    SQLite（元数据/血缘/授权）+ 内容寻址音频库            │
└──────────────────────────────────────────────────────────────┘
```

**层间硬约束**：

- L4 不得 import 任何引擎 SDK，只走 `Engine` 协议。
- L3 不含采样率、显存、模型名。IR 是纯音乐语义。
- L2 是唯一知道"哪个引擎在跑、还剩多少显存"的层。
- L1 引擎之间不互相调用，协作由 L2 编排。
- L0 音频只按内容哈希寻址，业务代码不拼路径。

### 3.2 唯一计划权威

> 任何引擎的内部 planner 输出，必须先解析成 IR 的候选 revision，经校验才能进入渲染。引擎不得直接决定段落、调性、BPM、和弦。

| 引擎 | 剥夺规划权的手段 |
|---|---|
| YuE2 | 传 `abc=` 自有谱 + `cot=off`；只在"从零起草"时允许 `cot=full`，结果必须导入 IR 供审阅 |
| ACE-Step | 显式传 BPM/key/拍号/时长/段落标签；禁用 query rewriting 与 simple mode |

### 3.3 任务 DAG（16 节点）

每个节点声明五件事：输入、输出、契约断言、失败回退、幂等键。

| ID | 节点 | 输出 | 契约断言 |
|---|---|---|---|
| N01 | ingest | `normalized.wav` + `src_ref.wav` | 时长 >3s；峰值 >-40dBFS |
| N02 | grade | `grade.json`（S/A/B/C） | 五项指标全算出，缺一即失败 |
| N03 | separate | `vocal_raw.wav` / `inst.wav` × 3 模型 | 三模型都返回；超时用已返回的 |
| N04 | fuse | `vocal_fused.wav` + `sep_qa.json` | 占比 0.25–0.65、残留 <-18dB、空洞率 <20% |
| N05 | f0extract | `f0.npz` / `voicing.npz` / `f0_conf.json` | 双路差异 >600 cents 帧占比 ≤1% |
| N06 | precheck_rvc | `gate.json` | 四项预检；任一不过给出 `shift_key`/`skip_rvc`/`reject` |
| N07 | rvc | `vocal_conv_{take}.wav` | 时长差 ≤50ms；无 NaN；峰值 ≤-1dBFS |
| N08 | coarse_rank | `ranked.json` | 至少 1 个 take 过粗筛 |
| N09 | repair | `vocal_repaired.wav` + `repair_meta.json` | 重建后 8–16kHz 能量比 ≥0.6 |
| N10 | breath | `breath_events.json` + `breath_audio.wav` | 事件数 >0；为 0 标 `no_breath_detected` |
| N11 | humanize | `perf_humanized.json` | 注入后 σ 在红线内，超限裁剪并记 `clamped` |
| N12 | space | `vocal_spaced.wav` + `space.json` | 人声与伴奏 RT60 差 ≤0.15s |
| N13 | layer | `layer_stems/` | 各层与 lead 时间偏差 ≤5ms |
| N14 | mix | `mix.wav` | mono 折叠后人声衰减 ≤3dB |
| N15 | master | `master.wav` | 真峰值 ≤-1.0 dBTP；LRA ≥8 LU；响度偏差 ≤0.5 LU |
| N16 | eval | `eval.json`（37 项）+ `report.md` | 37 项全算出；缺项标 `not_applicable`，不许填 0 |

**依赖图与并行支线**：

```
N01─N02─N03─N04─N05─N06─N07─N08─N09─┐
              │                     ├─N13─N14─N15─N16
              └──── N10 ────────────┤
                N11（依赖 N05）──────┤
                N12（依赖 N09）──────┘
```

- **N10 必须在 RVC 之前**：呼吸段没有基频，RVC 会把它当噪声处理掉。所以从 N04 的原始人声上裁，与 N05–N09 并行。
- **N11 只依赖 f0 数据**，与音频处理无关，可在任意时刻算。
- **N12 与 N13 可互换顺序**。

### 3.4 失败回退

失败不是报错退出，是"回到哪一步"。

| 失败节点 | 判定 | 回退到 | 重试 | 用户可见 |
|---|---|---|---|---|
| N01 | 解码失败 / <3s | — | 否 | 直接拒绝 |
| N02 | 分级 C | 继续（确认后） | — | 告知"做不出目标效果" |
| N03 | 全失败 | — | 换 CPU 1 次 | 拒绝 |
| N04 | 三项任一不过 | **回 N03 换模型组合**（≤2 次） | UVR→MDX23C→Demucs | "分离质量不足，已换方案" |
| N06 | 音域超限 | **插移调节点** | 自动移调到分布内 | "已自动移调 X 半音" |
| N06 | 判定 `skip_rvc` | **跳 N07–N09** 直到 N12 | — | "该曲走直通模式" |
| N07 | NaN / 时长不符 | 换 seed 1 次 | — | 失败则报错 |
| N08 | 全不过粗筛 | 取最高分，标 `best_effort` | — | "未找到理想结果，建议换源" |
| N09 | 重建不达标 | **换谐波激励** | 1 次 | 记录修复方式 |
| N10 | 未检测到呼吸 | 跳过贴回 | — | 报告标注 |
| N12 | RT60 差 >0.15s | 回退 dry | — | 记录 `space=fallback` |
| N13 | 叠层不齐 | 重对齐 1 次 | — | 仍不齐只留 lead |
| N15 | LRA <8 | **回 N14 降压缩比** | 1 次 | 仍不达标告警不阻断 |

### 3.5 幂等与增量

```
node_key = sha256(上游产物哈希 + 节点参数 canonical_json
                  + engine_id + engine_version + adapter_hash)
```

| 变更 | 失效范围 | 重跑耗时（4 分钟歌） |
|---|---|---|
| 改 humanize σ（N11） | N11–N16 | ≈30s |
| 换音色模型 | N07–N16 | ≈5min |
| 改混音预设 | N14–N16 | ≈2min |
| 换源 | 全部 | 11min |
| 引擎版本升级 | 该引擎相关节点 | 视范围 |

**这条决定调参效率**：没有它，改一个数要重跑 11 分钟；有它，30 秒。

## 4. 核心数据

### 4.1 Song IR 三层

```
L0  ScoreDoc      ABC 文本（YuE2 子集 + 扩展注释）   ← 人类编辑 / Git / 交付引擎
      ↕ parse / serialize（必须可往返，往返测试进 CI）
L1  ScoreGraph    结构化图（Note/Chord/Section/StableID）  ← Patch 作用对象
      ↕ compile
L2  RenderPlan    渲染指令（分片/重叠区/引擎参数/seed/graft 边界）
```

**为什么不是纯 MusicXML**：一个音符几十行 XML，diff 不可读，往返有损。MusicXML 只作导入导出通道。

**符号层与表现层分离**（关键）：

| 层 | 内容 | 载体 | 谁改 |
|---|---|---|---|
| 符号层 | 音高、时值、小节、段落、和弦、歌词音节 | ABC ↔ JSON | 用户 / LLM patch |
| 表现层 `Performance` | velocity 曲线、vibrato、气声比、articulation、混音预设 | JSON（按 NoteID 索引） | 曲线编辑器 / 引擎回填 |

`Performance` 是"情感细节保留度"的技术落点。翻唱时从源演唱提取的 F0 微轮廓、能量包络、颤音特征写入这里，渲染时作为条件传入。

### 4.2 核心字段

`ScoreGraph` 关键字段：`tempo_map`、`key`、`time_signature`、`sections`（id/label/start_bar/end_bar/energy）、`tracks`（vocal_lead / harmony / inst）、`notes`（id/bar/onset_ticks/dur_ticks/pitch/pitch_cents/lyric/source）、`chords`、`lyrics`、`form`。

**PPQ = 480**，全曲绝对 tick，避免跨段错位。

`NoteID = "n:" + sha1(f"{section}|{track}|{bar}|{onset_ticks}|{pitch}")[:12]`，编辑后靠 LCS 序列对齐迁移；迁移率 <90% 时升级为 ID 内嵌方案。

### 4.3 产物与血缘

| 字段 | 说明 |
|---|---|
| `artifact_id` | `sha256(canonical_params)` |
| `kind` | vocal / instrumental / mix / stem_* / f0 / midi |
| `path` | 内容寻址相对路径 `renders/ab/abc….flac` |
| `loudness_lufs` / `true_peak_db` | 入库时实测，不信任引擎自报 |
| `source` | `{engine_id, version, adapter_hash, seed, revision, node_id}` |
| `rights_ref` | 关联 RightsRecord，生成物继承输入的最小权限集（交集） |

### 4.4 授权台账

| 字段 | 说明 |
|---|---|
| `asset_id` / `type` | 资产 / `composition`、`master`、`voice`、`lyrics` 分开 |
| `license_type` | owned / exclusive / non_exclusive / cc0 / cc_by / statutory |
| `scope` | `["train","render","commercial","cover"]` |
| `territory` / `valid_from` / `valid_until` | 地域与期限 |
| `consent_ref` | **授权书文件的 sha256**，不是口头同意 |
| `revoked_at` | 撤销时间，置位后级联隔离派生资产 |

**三道门禁**（纯函数，可单测）：`assert_trainable` / `assert_renderable` / `assert_publishable`。失败返回 `RIGHTS_DENIED` 并指明缺哪个 scope、哪份材料。

## 5. 翻唱链路

### 5.1 输入分级

| 级别 | 判据 | 可达拟真度 | 处理 |
|---|---|---|---|
| **S** | 48k/24bit 干声，SNR >35dB，RT60 <0.25s | 最高 | A 入口直达 |
| **A** | ≥44.1k，SNR 25–35dB，安静房间手机录音 | 高 | 标准链 |
| **B** | 带伴奏成品，或 SNR 18–25dB | 中 | 集成分离 + 修复 |
| **C** | <128kbps、现场、明显削顶、SNR <18dB | 低 | **告知后仍可做，但明确说做不出目标效果** |

质检五项（纯函数）：有效带宽 / SNR / 削顶率 / 估计 RT60 / 码率。

C 级话术示例：

> "这条录音的有效带宽只到 11kHz，高频信息已经丢失。修复可以补一部分，但补出来的是推测的，会显得假。建议换一条清唱——手机自带录音机就行，安静房间，别开混响。"

### 5.2 分离

三模型并行，频点级融合（不是简单平均）：

```
对每个时频点 (t,f):
  一致性 > 0.9  → 取中位数
  一致性 < 0.6  → 取能量最低的（最保守，避免伪影叠加）
  其余          → 能量加权平均（权重按各模型频段表现配置）
```

**为什么不用平均值**：平均会让伪影叠加而不是抵消。中位数 + 保守选择才是正解；代价是高频略闷，由 §5.3 的高频重建补回。

三项门禁（不过则回 N03）：人声占比 0.25–0.65、伴奏残留 <-18dB、频谱空洞率 <20%。

**第三项最关键**：高频空洞不可逆。源本身低码率时，任何"重建"都是编的，会明显假。

### 5.3 修复

顺序不可换，每步为下一步准备：

```
① 去伪影（谱减 / 轻量扩散去噪）
② 去混响（仅当 RT60 >0.35s；强度上限 -30%）
③ 高频重建（8–16kHz 谐波补全）
④ formant 与音高一致性校正（仅移调时）
⑤ 底噪注入（在混音前，不在修复末尾）
```

**② 的条件执行是硬要求**：无条件去混响会削掉真人空间感——这恰好是"像不像现场录音"的核心线索。

**③ 两条路线**：带宽扩展（扩散，自然但 60–120s）优先；超时降级到谐波激励（快但易电子味）。

**④ formant 校正（v1.1 漏掉，不做会直接毁结果）**：

```
α = 1.0  大跨度移调（女→男，key ±12）
α = 0.5  ±2 半音内的微调
α = 0.0  同性别微调
目标 formant 缩放 = (目标音高 / 源音高)^α
实现：WORLD 分解谱包络 → 按 α 缩放 → 重合成 → 再送 RVC
顺序：先 formant 后 RVC，不可反
验收：LPC 估计前两个共振峰比值，与 α 目标偏差 >0.15 判失败
```

**⑤ 底噪注入（反直觉但关键）**：

数字静音是最强的"这是 AI"信号之一。真实录音永远有房间声。

```
1. 从源静音段估计噪声底（最低 5% 帧的中位数），记录频谱形状与电平
2. 在混音前注入（不是修复链末尾），电平 = 目标 + 压缩预期衰减
   衰减量从压缩器实例读出，不要估算
3. 目标：-62 ~ -48 dBFS
4. 母带后复测，偏离超 3dB 则在线性区回补（回补不再经压缩）
```

**为什么不能用源噪声直接贴**：源噪声里可能混有伴奏残留。用估计的形状 + 白/粉噪声重新合成更可控。

### 5.4 转换（RVC）

**能力边界先说清**：RVC 是声音转换，不是歌声合成。它**不教唱，只换嗓**——音准、节奏、气息全部继承源。

六个退化点，各有检测与处置：

| # | 退化 | 机制 | 指标 | 判据 | 处置 |
|---|---|---|---|---|---|
| 1 | 辅音被抹 | 内容特征在 16kHz 提取，4–10kHz 被截断 | `ConsonantClarity` | ≥0.6 | `protect` ↑；重建时提 8–12k 权重 |
| 2 | 瞬态变软 | 20ms 帧率抹圆 attack | `TransientRatio` | ≥0.75 | 瞬态重建；源 attack 包络调制前 30ms |
| 3 | 颤音压平 | 每帧单 f0 | `EDR_vib` | 0.8–1.2 | 贴回源 f0 微轮廓 |
| 4 | 八度跳错 | RMVPE 在气声/高音边缘锁低八度 | `OctaveErrRate` | ≤1% | 双路互校 + 置信度门限 + 人工修正 |
| 5 | 音域超限 | 超出模型 f0 分布 P1–P99 | `RangeOverflowRate` | ≤3% | 自动移调；或换宽音域模型 |
| 6 | 长音漂移 | 生成式声码器失稳 | 长音段 f0 标准差 | ≤15 cents | 分段 + 每段独立 f0 锚定 |

**前三项必然发生**（架构性，必须后处理补）；**后三项条件发生**（靠检测拦截）。

三档参数（帕累托前沿，不可同时最优）：

| 档位 | `index_rate` | `protect` | SECS | EDR |
|---|---|---|---|---|
| 音色优先 | 0.72–0.78 | 0.25 | ≥0.85 | ≥0.72 |
| 平衡（默认） | 0.58–0.62 | 0.33 | ≥0.82 | ≥0.80 |
| 情感优先 | 0.42–0.48 | 0.45 | ≥0.78 | ≥0.86 |

训练完成后自动扫 3×3 网格，把前沿存进 `AdapterManifest.eval.pareto_front`。前沿整体低于门禁 → 判训练失败，不允许调参调到过。

**SECS 对应的听感（不承诺超出）**：

| SECS | 听感 |
|---|---|
| <0.75 | 明显不是同一人，重做 |
| 0.75–0.82 | 同类声音，熟人能分辨 |
| 0.82–0.88 | 短片段多数认为是同一人（**验收线**） |
| 0.88–0.92 | 整曲多数分不出（需 30 分钟以上优质数据） |
| >0.92 | RVC 在歌声上的实际上限 |

**片段级像 ≠ 整曲级像**：整曲会暴露元音口型、音区共鸣、说唱连续性、笑声叹息等薄弱处。验收必须整曲算一遍 SECS。

### 5.5 拟真化层

这一层做"反向操作"：把修得太完美的地方重新弄得不完美。

#### 六个 AI 痕迹与对应处置

| 痕迹 | 听感 | 处置 | 可消除 |
|---|---|---|---|
| 缺呼吸与口腔声 | 唱得太顺，不像在呼吸 | 呼吸管线（下） | 能 |
| 过度干净 | 像消音室 | 底噪注入 | 能 |
| 音准过于完美 | 像修音修死 | humanize 注入 | 能 |
| 高频金属感 | 嘶嘶的 | 高频重建 | 部分 |
| 动态扁平 | 一直很响 | 分段响度 | 能 |
| 空间不一致 | 人声贴前面 | 空间匹配 | 能 |

#### 真人的七个不完美（验收标准来源）

| 特征 | 真人值 | AI 值 | 处理 |
|---|---|---|---|
| 音高偏差 | ±8–25 cents | ±0–3 | 注入 |
| 起音时刻 | ±12–35ms | ±0–5 | 注入 |
| 音符时值 | ±3–8% | ±0–1% | 注入 |
| 呼吸事件 | 4–12 次/分钟 | ≈0 | 保留/重建 |
| 底噪 | -62 ~ -48 dBFS | <-90 | 保留 |
| 动态范围 LRA | 8–12 LU | 4–6 | 分段处理 |
| 颤音 | 4–7Hz、20–60 cents、渐入 | 恒定或缺失 | 保留 + 微调 |

#### 呼吸管线（感知强度第一）

```
① 检测：voicing=0 + 能量高于底噪 6dB + 频谱重心 2–6kHz
② 从 N04 的原始人声裁（不是 RVC 输出）
③ 单独处理：电平比主唱低 12–18dB；用源的 formant 做轻微滤波
   ——绝不过 RVC：呼吸没有基频，会被当噪声处理掉
④ 按源时间戳贴回，前后各 30ms 交叉淡化
⑤ 口腔声（口水音/唇齿）：<80ms + 高频为主，同上但电平 +3dB
```

#### humanize（注入不完美）

```
σ_p（音高）默认 9 cents，上限 20
σ_t（时值）默认 14ms，上限 30
σ_d（音长缩放）默认 2.5%，上限 6%

shape(n) = 长音 1.0 / 短音 0.4 / 句首 0.3 / 句尾 1.2
   （长音与句尾最容易走音，真人如此）

颤音：保留源；仅当源缺失时按 4.8–6.2Hz、25–45 cents、前 30% 渐入补
```

**与修音的叠加（必须按公式，不能各调各的）**：

```
residual_cents = std(f0_slow - f0_target) × (1 - preserve_ratio)
σ_p_effective = 0                           if residual > 18
              = σ_p × 0.5                   if residual > 12
              = σ_p × (1 - residual/20)     otherwise
              再 clamp 到 [0, 20]
```

#### 空间一致性

```
① 从伴奏估计：RT60、早期反射密度（前 80ms）、分频段 side/mid 比
② 给人声加：4–6 个延迟抽头（8–45ms）+ 混响，RT60 = 伴奏 × 0.8–1.0
   预延迟 15–35ms（保证咬字清晰）
③ 校验：RT60 差 ≤0.15s；side/mid 比在 200Hz–4kHz 与伴奏差 ≤3dB
```

**常见错误**：混响加太多（"KTV 感"）。录音室人声是干的，靠早期反射而不是长混响。

#### 分段响度

| 段落 | 相对全曲 |
|---|---|
| 主歌 | -2 ~ -3 LU |
| 预副歌 | -0.5 ~ +0.5 LU |
| 副歌 | +1 ~ +2 LU |
| 桥段 | -3 ~ -4 LU |
| 尾奏 | 渐弱到 -8 LU |

段间 200ms 交叉淡化；最后整体线性归一到 -14 LUFS（只调增益，不压缩）。**LRA ≥8 LU 是门禁**。

#### 立体声

人声保持基本单声道（mono 能量 ≥85%），只通过早期反射制造宽度。**不用立体声扩展器**（haas 延迟会产生相位问题，单声道折叠后塌陷）。

#### 拟真化红线

| 红线 | 阈值 | 超出后果 |
|---|---|---|
| 音高注入 | σ_p ≤20 cents | 明显跑调 |
| 时值注入 | σ_t ≤30ms | 拖拍 |
| 高频增益 | ≤+1.5dB（8k 以上） | 变亮变假 |
| de-esser 范围 | 分频段，9kHz 以上不压 | 会削掉重建成果 |
| 混响 RT60 | ≤伴奏 × 1.0 | KTV 感 |
| 底噪 | ≤-48 dBFS | 像坏录音 |
| 去混响强度 | ≤-30% | 声音变干尸 |

### 5.6 叠层与母带

#### 人声叠层（真人主干 + AI 和声）

| 层 | 来源 | 电平 | 处理 |
|---|---|---|---|
| Lead | RVC 输出（或 A 入口的源） | 0 dB | 全部拟真化 |
| Double | 同模型换 seed；或 lead ±10ms / ±7 cents / 不同 EQ | -14 dB | 不做拟真化 |
| Harmony | 按 IR 和弦推三/六度，ACE-Step 生成或 lead 变调 | -17 dB | 轻拟真化 |
| Ad-lib | ACE-Step 在段落尾生成 | -22 dB | 轻拟真化 |

**硬约束**：所有叠层时间基准必须与 lead 完全一致（同一次 RVC 的 alignment），偏差 >5ms 出现"合唱团不齐"。

**必须制造差异**：真人叠层不会完全同步。时间 ±8–15ms、音高 ±5–10 cents、EQ 微差、混响 send 差 2–4dB。三个完全同步 = 电子合唱。

#### 母带链（七步，顺序不可换）

| 序 | 处理 | 参数 | 常见错误 |
|---|---|---|---|
| 1 | 低频单声道化 | <120Hz 合并，24dB/oct | 把 200Hz 也合并 → 低频闷 |
| 2 | 动态 EQ 去浑浊 | 200–400Hz，-2dB | 静态 EQ 一刀切 |
| 3 | 多段压缩 | 低 60–120Hz 慢(30/300ms,2:1)；中 1–4k 中(10/120ms,2.5:1)；高 8k+ 快(3/80ms,2:1) | 全段同比率 → 人声压扁 |
| 4 | 谐波饱和 | 2–4dB，混入 ≤30% | 过量 → 高频刺 |
| 5 | 立体声增强 | mid 保持，side +1.5dB（**<200Hz 不加宽**） | 全频加宽 → 单声道折叠塌陷 |
| 6 | 真峰值 limiter | -1.0 dBTP，lookahead 5ms | 只用 sample peak → 转码后失真 |
| 7 | 两遍响度归一 | 先测再线性增益 | 动态压缩式归一 → 动态被吃 |

#### 导出

| 用途 | 格式 | 响度 |
|---|---|---|
| 母带交付 | WAV 48k/24bit | -14 LUFS（可配） |
| 流媒体 | FLAC 48k/24bit | 同上 |
| 分享 | MP3 320 | 同上 |
| 二次制作 | stems 包（含未处理干声） | 不归一（保留动态） |

### 6.2 耦合矩阵（8 组，实现时变配置校验）

| 组 | 参数 A | 参数 B | 冲突表现 | 解 |
|---|---|---|---|---|
| A | `preserve_ratio` ↑ | `σ_p` ↑ | 净偏差不可控 | 用 §5.5 公式算 `σ_p_effective` |
| A | `index_rate` ↑ | `protect` ↓ | 音色更贴但咬字更糊 | 帕累托三档 |
| B | 降噪 ↑ | 底噪注入 ↑ | 注入被压缩吃掉 | 注入加压缩补偿 + 母带后复测 |
| B | 压缩比 ↑ | LRA 目标 ↑ | 不可同时满足 | LRA 硬门禁，压缩比让位 |
| C | 重建强度 ↑ | de-esser 范围 ↑ | 频谱塌陷 | 分频段 de-esser，9k 以上不压 |
| C | 重建强度 ↑ | 高频红线 +1.5dB | 超红线即变假 | 红线优先 |
| D | `σ_t` ↑ | 叠层对齐 ±5ms | 叠层不齐 | 先 humanize 再叠层 |
| D | `σ_t` ↑ | 段间淡化 200ms | 弹性被淡化吸收 | 淡化放在 humanize 之前 |

**组 D 是 v2.0 未识别的问题**：humanize 注入的 ±14ms 时值偏差会被 200ms 淡化窗口吸收掉，顺序必须先注入后淡化。

### 6.3 预算与降级

```
T_single(L) = 5 + 1.5L      # 单 take，L 为源时长（分钟）
T_best8(L)  = 6 + 1.5L + 2.0L
```

| 源时长 | 单 take | best-of-8 |
|---|---|---|
| 3 分钟 | 9.5 分钟 | 16.5 分钟 |
| **4 分钟** | **11 分钟** | **20 分钟**（卡线） |
| 5 分钟 | 12.5 分钟 | 23.5（超限，降 best-of-4） |
| 10 分钟 | 20 分钟 | — |

**超时降级顺序**：best-of-8 → best-of-4 → 双模型分离 → 谐波激励 → lead 变调 → 输出单 take 并标注。

**不允许**：跳过呼吸贴回或拟真化——这两项是目标核心，砍掉等于放弃目标。

### 6.4 best-of-N 分层筛选

昂贵修复只对胜出者做，否则预算立刻爆：

```
第一层 前处理（一次）        2.5min  分离+融合+f0+呼吸提取
第二层 RVC 8 take           8min    每 take 60s，扰动 seed/index/protect
第三层 粗筛                  0.5min  只用 f0 稳定/辅音能量/检测器，淘汰 6 留 2
第四层 精选 2 个做修复       4min    每个 120s
第五层 1 个做拟真化与收口    3min
```

**为什么粗筛够用**：修复不改变"音色对不对、f0 稳不稳"，只改善高频与伪影。先用便宜指标筛，质量损失很小。


SSE 事件：`stage` / `progress` / `artifact`（增量出结果）/ `warning`（降级提示）/ `error`。

### 7.2 引擎协议

```python
class Engine(Protocol):
    manifest: EngineManifest
    def probe(self) -> EngineHealth: ...
    def estimate(self, req: RenderRequest) -> CostEstimate: ...
    def render(self, req: RenderRequest, ctx: JobContext) -> RenderResult: ...
    def cancel(self, job_id: str) -> None: ...
    def unload(self) -> None: ...
```

**契约细节**：`render` 必须把产物写到 `ctx.out_dir` 并返回相对路径（跨进程不传 buffer）；`render` 内不得读数据库、不得发网络请求；`estimate` 必须比 `render` 快 100 倍以上；声明 `deterministic:false` 的引擎，缓存 key 必须含 seed 与 attempt。

### 7.3 调度

| 队列 | 内容 | 并发 | 超时 | 抢占 |
|---|---|---|---|---|
| `interactive` | 预览、粗筛 | 1 | 30s | 可抢占 batch |
| `fast` | 单 take 全链、分离 | 1 | 20min | 被 interactive 抢占 |
| `batch` | best-of-8、翻唱全链 | 1 | 40min | 不可抢占，可暂停 |
| `train` | RVC / LoRA | 1（独占） | 4h | 独占；期间 interactive 仅 DSP |

**显存仲裁**：`budget = 8192 - 800(驱动) = 7392MB`；准入 `estimate().vram_peak + Σ已加载 ≤ budget`；换出按 `last_used + reload_cost` 加权；为 Demucs/RVC 预留 1.5GB；单引擎峰值 >budget×0.9 直接拒绝（不让 CUDA OOM 兜底，OOM 后进程状态不可信）。

**冷启动**：ACE-Step 20–40s（启动即预热）、RVC 3–5s（按音色 LRU 缓存 3 个）、Demucs 5–8s（常驻）。

### 7.4 缓存

| 级 | Key | 命中收益 |
|---|---|---|
| C1 解析 | `sha256(abc + ppq)` | 100–500ms |
| C2 节点产物 | `node_key`（§3.5） | 30s–11min |
| C3 混音 | `sha256(stem 集合 + 预设 + 响度目标)` | 2–5min |

淘汰：总预算 20GB，`score = last_used / (size × (1 + rebuild_time/60))`，最小者先删。保护：当前 revision、最近 3 个、`published` 标记。

**key 必须含引擎版本与 adapter 哈希**——引擎升级后静默复用旧产物是最难查的一类缺陷。

**`HumanizeScore` 定义**（六子项，唯一"中间值最好"的指标，必须单测两端）：

```
H1 = in_range(std(cents_measured - cents_target), 8, 25)
H2 = in_range(std(onset_measured - onset_grid), 12, 35)
H3 = in_range(LRA, 8, 12)
H4 = in_range(breath_per_min, 4, 12)
H5 = in_range(noise_floor_dbfs, -62, -48)
H6 = in_range(vibrato_rate, 4.0, 7.0) ∧ in_range(vibrato_depth, 20, 60)

HumanizeScore = 0.25H1 + 0.15H2 + 0.15H3 + 0.20H4 + 0.15H5 + 0.10H6
```

### 8.2 真人判别测试（主验收）

```
材料：20 组三元组，每组 = 2 段真人演唱 + 1 段 Azzer 输出（同曲同段，15–25s）
任务：指出哪一段是 AI 唱的
评审：30 人（普通听众 20 + 音乐从业者 10）
主指标：识破率
判定：≤40% → "分不清"成立（随机基线 33.3%）
对照：同条件测 Suno 输出，作为校准基线
```

**必须测 Suno 对照**：如果 Suno 是 45%、我们是 40%，算达到；如果 Suno 是 25%、我们 40%，还差一截。"分不清"是相对标准。

**分层报告**：普通听众与从业者通常差 15–25 个百分点，只报总体会掩盖问题。

**替代验收**（Suno 不可得时）：与真人的 SECS/EDR/SPL 三项分位数对齐，作为代理指标。

### 8.3 症状诊断树

| # | 你听到的 | 先查 | 阈值 | 处置 |
|---|---|---|---|---|
| 1 | 咬字糊 | `ConsonantClarity` | <0.6 | `protect` +0.05；重建提 8–12k 权重 |
| 2 | 字头没劲 | `TransientRatio` | <0.75 | 瞬态重建；源 attack 调制前 30ms |
| 3 | 长音直 | `EDR_vib` | <0.8 | 贴回源 f0 微轮廓 |
| 4 | 某字突然变声 | 元音级 SECS | <0.75 | 重训或该段跳 RVC |
| 5 | 高音发紧 | `RangeOverflowRate` | >3% | 自动移调；换宽音域模型 |
| 6 | 塑料感 | `HNR` 偏差 | >3dB | 降重建强度；改谐波激励 |
| 7 | 像在浴室 | RT60 差 | >0.15s | 降 send；改早期反射 |
| 8 | 人声贴前面 | side/mid 差 | >3dB | 加 4–6 个早期反射抽头 |
| 9 | 一直很响 | `LRA` | <8 LU | 重做分段响度；降压缩比 |
| 10 | 音准抖/跳 | `OctaveErrRate` | >1% | 修 f0（低置信帧插值） |
| 11 | 像两个人唱 | 叠层时间差 | >5ms | 用 lead alignment 重对齐 |
| 12 | 结尾突然静 | 末段底噪 | <-62dBFS | 全曲铺底噪含尾奏 |

**诊断顺序**（上游错则下游调什么都是掩盖）：分离空洞率 → f0 八度风险 → 转换四门禁 → 修复强度 → 拟真化裁剪标记 → 混音母带。

最常见的浪费是"人声糊就去调 de-esser"，而实际原因是分离空洞率 35%。

## 9. 技术选型

> **本节已被 `Azzer-tech-stack-v3.1.md` 替换**（设计方不接受 Python 作为主语言，底层改用 Rust）。下表为 v3 原方案，保留供对照；实际实施以 v3.1 为准。

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | React 18 + TS + Vite、Zustand、TanStack Query | 生态与类型安全；状态高频更新 |
| 波形 | wavesurfer.js v7 | 成熟、支持 region |
| 播放 | WebAudio + 自研调度 | 需要多轨同步与 A/B 无缝切换 |
| 乐谱（重制档） | abcjs（编辑）/ OpenSheetMusicDisplay（只读） | abcjs 原生 ABC，与引擎对齐 |
| 钢琴卷帘 | 自研 Canvas/WebGL | 音符级拖拽与力度曲线，现成库都贴不上 |
| 后端 | FastAPI + uvicorn | 异步、SSE 原生、OpenAPI |
| 队列 | SQLite 表 + asyncio worker（MVP）→ Arq/Redis（V2） | 单机不需要分布式；状态与业务同事务 |
| 元数据 | SQLite（WAL） | 零运维；Revision DAG 用递归 CTE |
| 音频存储 | 本地内容寻址树 | 可 rsync、可换 S3 |
| 音频处理 | ffmpeg + soundfile + librosa + pedalboard | ffmpeg 本机已有多份 |
| 符号处理 | music21 + abcmidi | music21 生态全，abcmidi 语法检查最严 |
| 试听合成 | fluidsynth + SF2 | 无 GPU 也能听谱（M0 关键） |
| 观测 | structlog + 每节点 timing spans | 延迟必须可归因到节点 |

**双 venv 必然**（不是洁癖）：ACE-Step 要 Python 3.11、YuE2 要 3.12、RVC 依赖 fairseq 对版本极敏感。因此：

```
services/engines/{yue2,ace_step,rvc}/.venv/   # 各自独立
services/api/.venv/
```

每个引擎以 sidecar 进程运行，暴露内部 HTTP，由 `RemoteEngineAdapter` 调用。**本地与远端走同一适配器**——上云只是改 URL。

### 9.1 v3.1 的关键变更（摘要）

| 项 | v3 | v3.1 |
|---|---|---|
| 主语言 | Python | **Rust**（axum + tokio） |
| 模式推理 | PyTorch 进程内 | **ONNX Runtime（`ort`）进程内** |
| 分离 | 三模型集成（Python） | 基础档 htdemucs 单模型（纯 Rust）/ 高质量档可选容器 |
| 容器 | 必需（三个 venv） | **可选**（用户不装则走纯 Rust 降级路径） |
| 前端波形 | wavesurfer.js | 自研 Canvas 2D（多轨同步与性能） |
| 样式 | 未定 | CSS Variables + CSS Modules（不引 Tailwind） |
| 界面基调 | 未定 | 暗色克制 + 暖石/青绿双强调 + 波形为主视觉 |

**能力与代价**：纯 Rust 路径 D1 概率 35–50%，启用容器后回到 50–70%。差价全部落在"集成分离"与"扩散式高频重建"两个环节。

## 11. 风险与边界

| ID | 风险 | 触发 | 影响 | 缓解 |
|---|---|---|---|---|
| R1 | 源质量不足（C 级） | 低码率/现场 | 达不到目标 | 分级前置告知 + 引导重录 |
| R2 | 分离损失不可逆 | 成品源 | B/C 入口上限受限 | 三模型集成 + 修复；引导 A 入口 |
| R3 | 拟真化过量 | σ 调太高 | 真实变难听 | 红线硬编码，用户不可越过 |
| R4 | 检测器军备竞赛 | 新检测模型 | 指标漂移 | 只作辅助（权重 ≤0.25），不作门禁 |
| R5 | 判别测试样本量不足 | 30×20 偏小 | 置信区间宽 | 报 Wilson 区间；关键决策 60 人复核 |
| R6 | 20 分钟预算刚性 | 源长/设备慢 | 超时 | 降级顺序；优先保呼吸与拟真化 |
| R7 | 翻唱版权双重授权 | 发布 | 法律风险 | RightsRecord 双维度 + 发布前递归断言 |
| R8 | 高频重建编出假谐波 | 源空洞大 | 听感塑料 | 空洞率 >40% 判源不可用 |
| R9 | 叠层不齐 | 时间基准偏差 | 电子合唱感 | 5ms 硬约束 + 自动检测 |
| R10 | YuE2 非商业授权 | 商业化 | 阻塞 | 引擎可替换；发行版不含权重 |
| R11 | 缓存 key 漏字段 | 引擎/adapter 升级 | 静默脏读 | key 含 version + hash；金标准回归 |
| R12 | 指标过拟合自建基准 | 只对自己数据优化 | 上线体感不符 | 保留外部盲测 + 分层报告 |

**边界（明确不承诺）**：

- 不承诺"超越 Suno"；不承诺"商业发行水准"。
- 不承诺 SECS >0.92；不承诺提升唱功。
- 不承诺 C 级源可达标；不承诺 >10 分钟源不经分段。
- T0（8GB）不承诺"重制演绎"档（需 YuE2）。
